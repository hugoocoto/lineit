decide
- the editor and bisect take a code square's output as it comes: a line that
  arrives late can go to the next poll or the next recorded event (bisect's
  totals are whole, which event a line belongs to is best effort)
- a `while` that spins on a global in a compiled program takes its core: with
  more spinners than cores it starves the other branches (the branch tests
  did on Windows); yield in compiled loops that wait?
- a mirrored square counts as moved in a diff (layout), not as a change
- the pool's threads have 64 MiB stacks and there are as many as cores, not
  configurable
- hidden state that's still let through: Python, a class instance called
  through __call__, `import itertools as it`, an iterator only used in a
  `for`, a closure stored by unpacking or inside an `if`; Lua, closures made
  by indirect calls; C#, static properties of types lineit doesn't know
- stderr lines of a square come after its prints in the output, not in the
  order it wrote them (two pipes)
